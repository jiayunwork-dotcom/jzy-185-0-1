# 设计说明

## 1. 模块划分

| 模块 | 职责 |
| --- | --- |
| `app/solver/simplex.py` | 从零实现的两阶段**修正单纯形**（仅用 NumPy 解线性方程组），Bland 规则防循环 |
| `app/solver/lpmodel.py` | 原料/营养/比值/上下界约束 → 标准型 LP（等式行 + 松弛变量 + 人工变量） |
| `app/solver/analyze.py` | 影子价格、检验数、最优性三条件复核、价格灵敏度区间；退化影子价格扰动复核 |
| `app/solver/diagnose.py` | 不可行诊断：结构性快速检查 + 删除过滤求最小冲突集（IIS） |
| `app/services/ingredients.py` | 原料草稿编辑与不可变版本发布 |
| `app/services/formulas.py` | 配方规格新建/修改（修改即新版本） |
| `app/services/optimize.py` | 单次求解编排：组装 LP、求解、自证、灵敏度、异常解释 |
| `app/services/runner.py` | 版本解析、快照级校验、热启动装载、结果持久化、结果对比 |
| `app/services/scheduler.py` | 线程池异步作业：进度、协作取消、版本锁定 |
| `app/services/reprice.py` | 周换价作业装配：求受影响配方、冻结版本号、提交 |
| `app/storage.py` | SQLite（WAL）存储层，写操作进程内串行 |
| `app/validation.py` | 带字段路径的输入校验 |
| `app/api/` | FastAPI HTTP 接口（仅 HTTP，无页面） |

## 2. 数学模型与“自证最优”

决策变量 `x_i` 为第 i 种原料在 1 千克成品中的用量。

标准型：

```
min  cᵀx
s.t. A x = b,  x ≥ 0
```

- 总量：`Σ x_i = 1`（等式，人工变量起步）；
- 营养下界 `Σ n_ik x_i ≥ lb` / 上界 `≤ ub`，各加松弛变量；
- 比值约束（如钙磷比 `1.2 ≤ Ca/P ≤ 2.0`）线性化为
  `Σ(Ca−1.2·P)x ≥ 0` 与 `Σ(2.0·P−Ca)x ≥ 0`；
- 每种原料的上下界 `min_i ≤ x_i ≤ max_i` 也各占一行，保证上下界都有
  对偶变量与检验数。

接口返回的可代入检验内容：

1. **原始可行**：逐条代入 `Ax=b`、`x≥0`、`min≤x≤max`，给出最大残差；
2. **对偶可行**：所有真实列（原料列+松弛列）检验数 `r_j = c_j − A_jᵀy ≥ 0`，
   给出最小检验数；
3. **互补松弛**：逐列 `x_j·r_j = 0`，给出最大违例；
4. **对偶间隙**：`|cᵀx − bᵀy| / max(|cᵀx|,ε) < 1e-9`（实现实际精确到
   双精度舍入，通常为 0）。

每条约束返回 `active`（是否起作用）、`slack` 和 `shadow_price`
（影子价格，即约束右端放松一个单位时总成本下降率）；每种原料返回检验数与
状态（基变量 / 下界 / 上界）。

### 退化顶点的影子价格

退化时某个贴合的约束在当前基下可能带着非零对偶值，但放松它实际并不改变
最优成本（见测试中 CP=8 且全玉米恰为最优的例子）。`analyze.py` 对每条贴合
的不等式用 ±1e-6 的右端扰动**从最优基热启动重解一次**，按真实成本变化率
报告影子价格；只有真实边际成本非零的约束才标记 `active=true`。等式约束
（总量）保留基对偶值。

### 灵敏度区间

对每个原料价格给出 `[price_low, price_high]`：

- 基变量：基逆 `B⁻ᵀ` 推出各非基列检验数随价格扰动的变化率，取所有非基列
  保持非负的公共区间（经典 LP 价格灵敏度）；
- 非基变量（在 0 下界）：只需自身检验数保持非负，价格可降到
  `c − reduced_cost`；
- 区间端点取闭区间；区间内最优基不变，因而原料组成不变；越出区间必有非基
  列入基，组成改变（测试逐点验证）。

## 3. 退化、循环与确定性

- 进基与出基都使用 **Bland 规则**（最小下标入基、比值相持时取基变量下标
  最小者），数学上保证不循环；
- 所有候选列按固定顺序枚举，原料与营养按字典序/输入顺序排列，同一份输入
  每次得到完全相同的最优基与用量；
- 双精度漂移（微小负基变量）在每步钳零，末尾从 `B` 干净重算一次 `x_B,y`。

## 4. 热启动策略（真实取舍的选择）

**策略：按“同一 LP（含右端项）”复用最优基，价格小幅变化时跳过第一阶段；
约束集或右端变化时保守地整体放弃热基、冷启动。**

- 每次结果保存 `structure_key =（原料序列, 约束行序列, 标准型右端向量 b）`
  和最优基列索引。价格只进入目标函数 `c`，不出现在 key 里，所以改价后
  key 一致、基可以复用。
- 提交求解时：key 一致才尝试旧基；先解一次 `B x_B = b`，**只有基可逆且
  原始可行（所有基变量 ≥ −1e-8）且基中不含人工变量**才跳过第一阶段，
  否则走完整两阶段冷启动。这覆盖了“基失效”的两类情形：
  1. 约束集/上下限/营养限值变化（key 直接不匹配，保守冷启动）；
  2. 营养含量变化使旧基在新数据下不再原始可行（key 匹配但可行性校验失败，
     自动回退冷启动）。
- 价格小幅变化时旧基天然原始可行，热启动只剩第二阶段的几次转轴
  （测试 `test_warm_start_skips_phase_one` 验证 `phase1_iterations==0`）。
- `test_warm_and_cold_match_across_price_changes` 对多组价格变化同时跑
  热启动与强制冷启动，断言两者最优成本相对差 < 1e-9、逐原料用量一致。
- 热启动是纯性能优化，绝不改变答案；不可行诊断只在冷启动第一阶段确认
  不可行后触发。

## 5. 不可行诊断

不止回“无解”。`diagnose.structural_checks` 先做 O(n log n) 的结构性检查，
每条冲突给出 `code`、中文说明、涉及约束标签和“证据”原料：

- `max_inclusion_below_total`：各原料最大比例之和 < 1；
- `min_inclusion_above_total`：各原料最小比例之和 > 1；
- `nutrient_lower_unattainable`：营养下限高于按上限可达到的最大值
  （用带总量=1 的“裁剪-分配”贪心求极值，并列出贡献最大的原料）；
- `nutrient_upper_unavoidable`：营养上限低于按下限不可避免的最小值；
- `ratio_lower_infeasible/ratio_upper_infeasible`：比值线性式极值检查。

结构性检查未命中但单纯形判不可行时，回退到**删除过滤（deletion filter）**：
逐个移除宏观约束，若剩下的约束仍不可行就永久删除，最终留下一个最小冲突集
`irreducible_infeasible_subset`。该路径仅在异常情况下运行，40+ 原料规模
下调用次数有限。

## 6. 版本与作业并发

- 原料库：草稿表可增删改；`publish` 生成不可变版本，整库快照到
  `ingredient_snapshots`，营养项 code 自动登记。
- 配方：每次修改写入新版本行；结果只绑定
  `(formula_version, library_version)`。
- **版本锁定**：换价作业提交时就把库版本和每个配方的当前规格版本解析好
  存到 `jobs/job_items`。作业运行期间发布的新版本对它完全不可见——
  `test_version_lock_during_running_job` 在线程处理中途发布 v3，断言
  作业结果仍标注 v2。
- **取消**：取消标志在每个配方处理之间协作检查；取消后在单个事务中
  删除该作业已产生的全部 optimization 行，item 全部标 `cancelled`，
  不留半批结果（`test_cancel_leaves_no_partial_results`）。
- **不互相覆盖**：optimization 表只追加、各自独立 ID；两个作业同时处理
  同一配方产生两行完整结果（`test_concurrent_jobs_same_formula_do_not_clobber`）。
- 作业进度 `{done,total}`、每 item 状态、succeeded/failed 计数均可查；
  不可行配方记为 item `infeasible` 且保留其诊断结果行，不拖垮整批。

## 7. 存储与部署

- SQLite 数据库文件落在 `FEEDOPT_DATA_DIR`（容器内 `/data`，挂载卷），
  WAL 模式；进程内写锁串行化所有写事务，线程池 worker 共享连接工厂。
- 镜像基于 `python:3.12-slim`，仅暴露 HTTP（`uvicorn app.api.app:app`），
  无页面。

## 8. 手算算例

玉米 CP 8%、0.30 元/kg；豆粕 CP 44%、0.50 元/kg；CP ≥ 18%，总量 1kg：

```
x_sbm = (18−8)/(44−8) = 10/36 ≈ 0.27778
x_crn = 26/36 ≈ 0.72222
cost  = 0.30·26/36 + 0.50·10/36 = 12.8/36 ≈ 0.35556
```

CP 影子价格 `(0.50−0.30)/(44−8) = 0.005556`（每放松 1 个百分点-千克）。
